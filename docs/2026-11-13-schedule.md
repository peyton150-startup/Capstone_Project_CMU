## Design decision — preserve meaningful LLM reasoning

**In rapid triage, use Python for observable facts, routine workflows, and hard safety gates; keep the LLM responsible for hypothesizing and concluding.** This is an Agentic AI capstone, not an attempt to replace the reasoning model with a fault classifier. The LLM's added value is interpreting competing causes and synthesizing a defensible diagnosis after deterministic evidence collection and tests.

| Existing Graph stage | Owner in the proposed triage design | Explicit boundary |
|---|---|---|
| **Observe** | **Python** | Collect and qualify source-linked sensor evidence; never infer the root cause from a score. |
| **Manual** | **Python eligibility gate; retrieval as needed** | OEM guidance is context, not physical proof of a current fault. |
| **Plan** | **Python** | Compile standard diagnostic questions; permit LLM fallback on unknown/unmapped symptoms. |
| **Investigate** | **Python + conditional LLM** | Python selects valid routine reads and interprets numerical/temporal predicates; ask an LLM when the next diagnostic step genuinely needs nonroutine reasoning. |
| **Hypothesize** | **LLM** | Generate and revise plausible causes, alternatives and uncertainty; preserve normal/transient, unknown and simultaneous faults. This stage is **not being replaced** in these five branches. |
| **Test** | **Python** | Check evidence validity, rival discrimination, window sufficiency, and independent physical sources. |
| **Conclude** | **LLM** | **Keep the existing model conclusion call as the normal path.** Model synthesizes the evidence, weighs competing hypotheses, states confidence/unknowns, and recommends next technician checks. **Do not replace with rules, a classifier, or a Python-authored causal conclusion.** |
| **Conclusion validation** (within conclusion handling, not an extra Graph node) | **Python** | `check_conclusion()` and triage-only clearance gates validate citations, open rivals, data coverage and the supported/no-action claim. They may downgrade an unsafe conclusion, **not invent a diagnosis**. |

**Failure behavior:** If the conclusion model fails or times out, preserve the existing safe unresolved/undetermined disposition and escalation path. Python may **format** an evidence/unknowns report, but must not fabricate the LLM's causal conclusion or call that fallback an LLM diagnosis. The five workstreams below do not change deep-mode behavior.

## Today's ordered work blocks and exit gates

### Block 0 — Freeze the control and safety invariants

- [ ] Record `main` SHA, provider/model configuration, 90-second/6-call triage budget, existing feature flags, and fixed known-answer/held-out seeds.
- [ ] Capture A0 comparators: model calls by stage, time to first valid hypothesis, latency p50/p95, actual qualified evidence, unanswered questions, timeout count, reported unknowns, and false-clearance cases.
- [ ] Add triage-only negative test expectations for KA-09-style multiple faults, missing/omitted machine, stale readings, null-primary rival question, and repeated derived views of one sensor.
- [ ] Establish **deep-mode unchanged** tests before implementation.

### Block 1 — Plan (primary objective today)

- [ ] Create a deterministic triage planner for recognized, observable anomaly categories (vibration, temperature, following error, hydraulic pressure, load, and quality/event symptoms when capabilities permit).
- [ ] Build typed question templates from **actual** trigger, machine scope, sensor capabilities, operating mode, and available evidence; include required window, valid sample count, physical source, comparison, and counterevidence objective.
- [ ] Return the existing `Question` contract (or backwards-compatible optional predicate metadata); do not create unverifiable prose-only “done” conditions.
- [ ] Retain “unknown cause,” no-fault/transient, and multiple-fault possibilities. Fallback to the LLM only when templates cannot cover the symptom or a genuinely novel causal question arises.
- [ ] Gate the substitution strictly on triage mode and an opt-in flag. **Do not alter `ModelPolicy.plan` for deep mode.**

**Exit:** recognized cases generate valid plans without a `plan` LLM call; unknown/unavailable cases produce a safe fallback; deep test snapshots remain unchanged.

### Block 2 — Observe (dependency for trustworthy planning)

- [ ] Reuse `observe()`, existing screening, and `gather(..., interpret=False)` for traceable evidence collection.
- [ ] Replace optional fixed-order context calls with a bounded, capability- and trigger-aware packet: target/line identity, sensor windows, status/operating mode, quality, physical-source lineage, receipt/observation cutoffs, and missing reasons.
- [ ] Preserve the six research-call default and show separately what was mandatory, optional, failed, skipped, repeated, and actually qualified; do not count the same data twice.
- [ ] Maintain the recorded-machine boundary: never pretend a simulator healthy-line baseline exists on a real CNC.

**Exit:** at an equal tool-call budget, the packet obtains useful eligible observations earlier without hiding other-machine or compound-fault evidence.

### Block 3 — Test (small, deterministic correctness engine)

- [ ] Implement a triage-only question/predicate evaluator returning `true`, `false`, `insufficient`, `stale`, or `unavailable` from qualified sensor windows and provenance.
- [ ] A successful tool response **alone** must not complete a diagnostic question; require the applicable count, state, time interval, validity and measured predicate.
- [ ] Keep H1-versus-H2 questions open when `hypothesis_id` is null but `distinguishes_hypothesis_ids` names live rivals.
- [ ] Deduplicate supporters by physical sensor/source root; raw readings, alarms, and summaries derived from one channel do not count as independent corroboration.

**Exit:** insufficient/stale results cannot close questions, rival tests remain open, and source duplication cannot manufacture support; deep semantics remain untouched.

### Block 4 — Investigate (algorithmic tool choice)

- [ ] Compile allowed `CallTool` requests from the pending questions, eligible tools/channels, known machine IDs, qualified time bounds, row limits, and remaining budget.
- [ ] Rank by expected discrimination **without inventing probabilities**: unresolved rival separation, counterevidence, signal trust, prior coverage, and cost; use stable ties.
- [ ] Begin with advisory selection compared to the existing `decide()` ordering. Only enable execution in a separately tested triage arm.
- [ ] Preserve a model escape hatch for ambiguous/unknown causality, but eliminate redundant standard `decide` and numeric interpretation questions where validated Python is sufficient.

**Exit:** fewer invalid/repeated requests and model decisions, with no loss of relevant or falsifying observations on held-out cases.

### Block 5 — LLM Conclude + Python conclusion validation (preserve reasoning, enforce safety)

- [ ] **Keep the existing triage `ModelPolicy.conclude()` LLM call as the primary and normal concluding path.** The model synthesizes source-linked observations, hypothesis/test results, competing explanations, contradictory evidence, uncertainty, confidence, and proposed technician next checks. Do not replace the reasoning model with deterministic root-cause selection, a decision tree, or a model-free conclusion generator.
- [ ] Improve the **information shown to the concluding LLM** (bounded and provenance-linked), including tested vs. untested rivals, qualified normal/abnormal windows, missing channels, and disagreement; do not treat missing evidence as evidence of absence.
- [ ] Preserve existing Python `check_conclusion()` and `needs_deep_run()` duties. Extend `triage_clearance_gaps()` rather than duplicating it: compare available screening with an independently validated expected-machine roster, qualified normal observations, independent supporting sources, and unresolved rival questions. These checks **may downgrade or escalate an LLM conclusion but must not choose a cause for the LLM**.
- [ ] Never turn missing or uncertain observations into `supported/no_action`; escalation remains the safe default where evidence is insufficient. A classifier or statistical anomaly score alone cannot authorize clearance or intervention.
- [ ] Build a typed, source-linked **read-only triage report** from the LLM conclusion **after Python validation**. On LLM failure/timeout, emit only a conservative `unresolved`/`insufficient_evidence` factual summary and escalation—**not** a generated causal diagnosis.
- [ ] Record and test the conclusion-model call separately from the Python validation time. Do **not** optimize away this model call merely to improve the 90-second benchmark. Protect its time budget by reducing routine calls in earlier stages.

**Exit:** valid triage cases reach the model-backed conclusion when time allows; no Python-generated causal conclusion substitutes for the model; KA-09/compound and omitted-machine variants cannot false-clear; genuinely healthy, sufficiently supported LLM conclusions may still clear after Python verification.
