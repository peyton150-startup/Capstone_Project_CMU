CLI reported low decide reasoning effort and late decide thinking off. Record the full settings/config and exact commit SHA before controlled A1/A2/A3/A4 comparisons.
- **Local setup:** `uv run python -m pytest tests/test_triage.py tests/test_recorded_investigation.py tests/test_agent_loop.py -q` passed **89/89 in 15.85 seconds** before A0.
- **Local run output:** `triage-a0-r1.records.jsonl` and `triage-a0-r2.records.jsonl`, stored outside Git. This note intentionally includes no credentials, shop data, or unpublished raw captures.

## High-signal evidence and failure mechanisms

### P0 for the next triage-only code PR: false clearance of a compound fault

In `KA-09-challenge`, repetition 2, the model concluded a vibration alarm was a transient spike and returned **confidence 0.85, `assessment=supported`, `recommendation=no_action`**; the case has **two true faults**. The trace says `hypothesize stop: timeout` and no new test-stage tool read was recorded before the conclusion. It produced `deep_recommended=false`: the triage result closed instead of escalating. This is observed false reassurance, not an assertion that either controller intervention was actually performed.

Relevant implementation: `agent/investigation.py:check_conclusion` accepts model-declared support after its current gap checks; `needs_deep_run` treats checked `supported/no_action` as closed. Proposed regression: absent sufficient relevant *normal/negative* evidence and unresolved rivals, no-action must remain `unresolved/escalate`; a genuinely measured benign transient may still close safely. **No hidden truth may be passed into the runtime validator.** This maps to [TRI-02](../TRIAGE_FUTURE_WORK_20261112.md#tri-02) and [TRI-22](../TRIAGE_FUTURE_WORK_20261112.md#tri-22).

### High: hypothesis and test work is starved by model latency

**25/26** runs report a timeout, the triage p95 is approximately the 90 s deadline, and no new test-stage reading was observed. Several runs spend approximately **46 seconds** waiting on a primary `plan` model attempt before a fast fallback responds; other `decide` and `hypothesize` attempts are cut off by remaining per-question deadlines. The CLI reports **93 time-cut-off attempts** total across two repetitions. A0 supports investigating stage-specific latency and routing, but it does not by itself establish which individual change will improve accuracy.

Proposed sequence: capture per-job primary/fallback duration and outcomes; introduce hypotheses-first as a **separate opt-in A1 arm** after the safety fixes and offline graph tests; compare against unchanged A0. Batch reads (A2) and read-ranking (A3 advisory, A4 executive) are subsequent *separately controlled* live arms, not yet tested in this baseline. This maps to [TRI-01](../TRIAGE_FUTURE_WORK_20261112.md#tri-01), [TRI-13](../TRIAGE_FUTURE_WORK_20261112.md#tri-13), [TRI-14](../TRIAGE_FUTURE_WORK_20261112.md#tri-14), and [TRI-15](../TRIAGE_FUTURE_WORK_20261112.md#tri-15).

### High: repeated/invalid tools and non-diagnostic reads

The trace includes **24 already-asked-at-this-tick skips**, particularly repeated `get_line_screening` requests, and **6 failed tool calls**, including missing required `to_tick` and excessive `get_events` rows. Repetition two `KA-09` attempted two readings lacking `to_tick` before reaching the six-call limit. Repetition one `KA-06` tried a 384-row `get_events` request (above the 300-row limit), then repeated it and stopped without useful evidence. Automatic `get_time` and `search_manual` consume research-call capacity; initial simulator `get_line_screening` has separate screening accounting. The 58 diagnostic-stage reads include 16 outcomes marked `uninterpreted`.

Do **not** turn off useful screening to solve this. Instrument the number and purpose of mandatory, discretionary, failed, repeated, interpreted and test-stage reads and compare prompt-visible coverage. Evaluate budget-aware manual retrieval and bounded read selection in *triage only*. This maps to [TRI-11](../TRIAGE_FUTURE_WORK_20261112.md#tri-11), [TRI-12](../TRIAGE_FUTURE_WORK_20261112.md#tri-12), [TRI-16](../TRIAGE_FUTURE_WORK_20261112.md#tri-16), [TRI-23](../TRIAGE_FUTURE_WORK_20261112.md#tri-23), and [TRI-31](../TRIAGE_FUTURE_WORK_20261112.md#tri-31).

### Existing correctness work remains mandatory, not independently proved by A0

Even without a specific live reproduction of each case, keep focused offline negative tests for **rival-separating questions whose `hypothesis_id` is null** ([TRI-03](../TRIAGE_FUTURE_WORK_20261112.md#tri-03)) and **multiple derived views of one physical channel being counted as independent support** ([TRI-04](../TRIAGE_FUTURE_WORK_20261112.md#tri-04)). These are code-review findings; do not label them as direct measured A0 failures.

## Evaluation validity and restrictions

1. The CLI printed **`0/0 root causes correctly identified (13 not judged)` in each repetition**. This is **missing diagnostic labels**, not 0% accuracy or proven correctness. The report's `4/13 right recommendations`, `3/13 resolved`, and `0 unnecessary interventions` are not equivalent to verified correct root-cause classification in read-only triage. Do not advertise any of them as diagnosis accuracy.
2. This is an **A0 measurement-only result**, not an acceptance pass for safe deployment. Retain the original two local JSONL files unchanged; collect their hashes, `git rev-parse HEAD`, model routing, sampled request metadata, dates and fixed seed list before the next live comparison. Raw records remain outside Git.
3. The result tests the **existing simulator monitoring + automatic statistical line screening**, not the unintegrated standalone real-data monitoring/Siemens anomaly pipeline. `LINE_CONTEXT=off` disables only the optional pre-plan incident packet; `STAGE_CONTEXT=off` does not remove this screening.
4. A0 is live-model but simulated-factory; **no real machine or shop telemetry was involved**. Real Siemens eligibility and data-quality gates remain mandatory separately. No existing deep investigation logic, interventions, memory or verification should change as a consequence of this finding-only PR.
