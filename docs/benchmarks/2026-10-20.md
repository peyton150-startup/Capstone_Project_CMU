# Provider benchmark, 2026-10-20

Live, real models, the developer's keys. Command, once per model:

    MODEL_REQUEST_SECONDS=45 MODEL_QUESTION_SECONDS=90 MODEL_MAX_OUTPUT_TOKENS=8192 \
        python -m capstone.benchmark <model> --seeds 0 --out <dir>

Every job given the one model alone, with no fallback. Three retries with
pauses of 2, 4 and 8 s, the default `Budgets` of the time (900 s per
investigation, 300 s of it kept for the follow-up). Each of the four faults on
seed 0: **four episodes per model, so every number here is small.** The developer
chose the models (Groq qwen3.8-27b and Mistral were left out: on 2026-10-20 Groq's
free tier refused our ~5,000-token prompts per minute and the Mistral key was
rate-limited on every request). The models ran at the same time, two of them on
NVIDIA's API, which may have slowed each other a little. Raw calls, one line per
episode: `2026-10-20-calls.jsonl` (it names each episode's true fault: for the
experimenter only).

- nemotron lightning 30b: request 40 s, question 80 s, investigation 43 s (from only 8 answers); failed requests: timed out 7

## What each model did

- **nemotron 120b** (the default): the only model that fixed a fault. Bearing:
  named CNC-03, the bearing was replaced and the fault was gone, but the run hit
  900 s while checking the fix. Bad batch and false alarm: concluded, asked for
  nothing (right). Wrong setting: blamed the material batch, no fix; ended
  "model unavailable" after 711 s. 15 invalid `decide` replies.
- **command-a-03-2025**: fast and reliable, but it never asked for the fix the
  bearing or the setting needed (stopped "no useful action" both times).
- **nemotron lightning 30b**: most replies invalid (13 of 23), mainly `decide`.
- **command-a-reasoning-08-2025**: answered `plan`, then HTTP 422 to every
  `decide` question. A minimal `decide` request is accepted, so the full prompt
  (working memory plus the tool list) is what it rejects; cause not found.

## Limits and the job table, set from these numbers

- `MODEL_REQUEST_SECONDS` stays 45 s and `MODEL_QUESTION_SECONDS` 90 s: the
  default model's slowest 5% took 36 s, so 45 s covers it with one retry or the
  fallback inside 90 s.
- `Budgets.timeout_seconds` 900 -> **1,200 s** (`followup_seconds` 300 -> 400):
  the default model needed about 948 s and timed out twice at 900 s.
- `MODEL_RETRIES` 3 with doubling pauses (set the same day): 18 of the default
  model's failures were HTTP 500s that clear within seconds.
- **Job table: unchanged.** nemotron 120b answers every job: it is the only
  model that carried out a needed fix. For availability, set
  `FALLBACK_MODEL=cohere/command-a-03-2025` in `.env` (fast, 94/98 valid);
  it is not a code default, since it needs a Cohere key.

## Not measured

One seed per fault only (the developer's time); no diagnosis labels (the
benchmark records actions, not whether the words name the right cause); the
compound challenge was not benchmarked.
