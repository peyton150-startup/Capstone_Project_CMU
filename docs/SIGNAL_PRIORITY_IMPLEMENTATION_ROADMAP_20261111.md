# Signal-ranked implementation roadmap: agent security, Siemens data, intelligence and observability

**Date:** 2026-11-11. **Scope:** Proposed implementation work for one consenting DMG MORI/Siemens pilot. **Status:** Documentation only; not a claim of implementation, machine approval or test success.

**Priority rule:** Only #1 and #2 are HIGH. Items #3–36 are MEDIUM, with conditional long-horizon items dormant until their gates are met. This is a prioritization of this newly collected workstream, **not a downgrade** of previously mandatory P0 source authorization, real-machine acceptance or safety/release controls in [SDC-01–20](SIEMENS_DATA_ACCEPTANCE.md), [RMI-01–07](REAL_MACHINE_INTELLIGENCE_ACCEPTANCE.md) or [MVP_SCOPE](MVP_SCOPE.md). Explicitly rejected noise from the earlier discussion is excluded.

**Developer decisions recorded after this ranking was written (2026-11-11):** (a) The pilot reads the machine through **Siemens adapters only**; MTConnect is not being pursued for now, so where an item below says existing MTConnect paths partly support it, read that as background, not as the planned route. The "redirects" denial in #2 concerns the MTConnect HTTP collector and is not active work. (b) #2 is the acceptance checklist for the read-only Siemens OPC UA adapter. (c) #29 (Kubernetes or a service mesh) is **not active**: `AGENTS.md` section 4.5 rules it out unless the developer changes that rule. (d) Items #3–11 are MEDIUM only inside this queue; where SDC-01–20 or RMI-01–07 make the same work P0, P0 stands.

### Guardrail GR-2 — Deterministic near-duplicate read coverage (item 34, MEDIUM; Evaluation, benchmarking and reasoning)

**Priority within this trio:** implement first, but only as a separate opt-in runtime PR after the developer-teaching gate. **Status: NOT BUILT.** A reported 2026-10-31 KA-01-bearing archived example used 14 `get_sensor_trend` calls among 20 research calls and still ended unresolved; **recount this baseline in the named archived fixtures before citing it as validated experimental evidence**.

**Verified existing code:** `agent/loop.py:call_signature` uses exact (tool name, sorted arguments, last tick); `gather` refuses an exact signature from `state.seen_calls`, not overlapping ranges. `providers/factory.py` defines typed `TickRange`/window arguments and tool schemas. Exact-repeat protection must remain unchanged when disabled.

**Plan (off by default):**

- Add `near_duplicate_guard: bool = False` (`NEAR_DUPLICATE_GUARD`) and a documented, finite `near_duplicate_overlap` (initial candidate 0.8, independently tune 0.6 and 0.9). Propagate through Settings/InvestigationDeps, no silent default enablement.
- Track each **successfully answered** window with tool, **fully qualified** machine and physical channel/sensor ID, observed `from_tick`, `to_tick`, source/time epoch, immutable data snapshot/as-known cutoff, permitted unit/quality and resulting evidence IDs. Compare **union of valid answered coverage**, not merely previous requested ranges or untrusted partial responses.
- Before a standard research read in `gather`, if an eligible earlier answer already contains at least the configured share of the new window **and no new time/data/capability exists**, mark `near_duplicate_call` without executing it. Record a bounded safe note naming previous evidence IDs, missing coverage and another genuinely useful query; increment a separate counter and the existing unproductive-step accounting.
- Tool equivalence must be **proven**, not assumed: `get_readings`, `get_sensor_trend`, and `get_sensor_summary` may share a sensor family but can answer different questions. Suppress a summary after raw readings **only** when those readings have enough source fidelity and verified computation to answer the requested summary. Do not suppress a new statistic, changed schema, changed baseline, historical arrival, changed quality or a fresh window.
- No suppression of `wait`, `get_time`, manual/recall, actions, a critic's bounded independent read, or verification/follow-up phase reads. Preserve existing strict budget and termination logic; a "no useful call" outcome must never assert machine health.

**Positive/negative tests:** identical/shifted tick windows with >=80% validated overlap and identical snapshot (refuse); partially available prior answer (allow); different machine/axis/signal (allow); same machine new epoch or corrected data (allow); latest-time extension (allow); a genuinely new computed statistic (allow); critic and verification reads (allow); guard off produces exactly the legacy trace and call count. Measure 13 frozen cases with paired seeds/models/settings: tool calls cut, nonproductive calls, p50/p95 wall time, correct/supported vs unresolved, dangerous misses, and invalid action decisions.

**Acceptance:** no suppressed call can have supplied previously unavailable decision-relevant information; speed benefit must not worsen diagnosis or abstention. **References:** [value-of-information research](MVP_SCOPE.md#fw-voi-stop), [existing SM-5 time-aware statistics](MVP_SCOPE.md#fw-sm-time-stats).

### Guardrail GR-1 — Controller-owned, once-only validation repair (item 35, MEDIUM; Evaluation, benchmarking and reasoning)

**Priority within this trio:** second, opt-in and one implementation PR. **Status: NOT BUILT.** The proposal reports roughly 12 invalid model answers out of ~2,000 answered questions and two `invalid_decision` endings in archived 2026-10-31 master batches; **verify these numbers before using them as success claims**.

**Verified existing code:** `ChatClient.ask` validates typed answers, `FallbackClient.ask` returns invalid formats as `ValueError` without hiding them behind provider fallback, `ModelPolicy._ask` records `invalid_reply`, `agent/loop.py:ask_policy` handles policy errors, and `agent/investigation.py:check_conclusion` can refuse unknown evidence/hypotheses while other gaps downgrade the conclusion. These are existing safety properties, not missing guardrails.

**Plan (off by default):**

- Add `repair_retries: int = Field(default=0, ge=0, le=1)` with `REPAIR_RETRIES` and wire it into `InvestigationDeps`; additionally cap total repair attempts **per episode** (suggest initial max 1) to prevent one extra model call per step. Default 0 must preserve bytes, calls and metrics on reference fixtures.
- Add ephemeral `repair_note: str | None = None` in `InvestigationState` and only expose it in the approved prompt renderer while a controller-owned repair is pending; never change `ReasoningPolicy` or let the model write the note. Clear it in `finally` on success, failure, timeout and cancellation.
- On recognized *schema/policy* refusal in `ask_policy`, retry the **same policy question at most once** only when enough of its existing question and episode time budgets remain (initial example >10 s; measure). The note must use **sanitized deterministic local validation messages**—field/expected type or IDs originally supplied by the model. Never echo raw provider body, provider exception, data secrets, shop contents or hidden simulator ground truth.
- At `conclude`, distinguish **hard rejection** (unknown E/H identifiers, malformed typed answer) from **soft downgrades** (`unresolved`, unsupported numeric claim, insufficient evidence). A hard refusal may be safely re-asked once; a soft downgrade cannot be automatically "repaired" into supported or intervene, and verified arithmetic still runs. Preserve `check_conclusion`, confidence/action threshold, human approval, model-unavailable and timeout behavior.
- Mark attempts and outcome in existing `ModelCall`/DecisionRecord/ReasoningMetrics with a consistent versioned enum/schema or separate repair metadata, preserving historical record compatibility. Do not silently relabel initial `invalid_reply` as success. Log metadata only.

**Positive/negative tests:** first reply invalid then valid (one bounded repair, no extra unproductive-step penalty); two invalid replies (same safe terminal fallback as existing behavior and two recorded calls); unknown `E99` or `H4` rejected with only those identifier references in the note; a numeric mismatch still downgrades, does not authorize action; expired budget/model unreachable not retried; secret-echo injection excluded; `REPAIR_RETRIES=0` byte-for-byte baseline. Matched 13-case replay comparing off/on: repaired count, invalid conclusions, false reassurance, accuracy/abstention, extra model seconds and tokens.

**Acceptance:** repair costs and safety consequences are measured, not assumed; explicit tests show no action elevation, no evidence fabrication, no hidden-state leak. **Reference:** [Pydantic runtime reliability evaluation](MVP_SCOPE.md#fw-runtime-audit).

### Guardrail GR-3 — Per-source channel-quality eligibility and evidence-aware conclusions (item 36, MEDIUM; Tooling and infrastructure)

**Priority within this trio:** third, with **existing Siemens SDC data-quality P0 gates unchanged**. **Status: NOT BUILT.** This proposes *wiring* existing capture-quality helpers into current agent-facing policy/tools; it does not replace native Siemens-quality validation.

**Verified existing code:** `ingestion/quality.py:unavailable_spans` and `stale_channels` are separate capture analytics. `recorded_investigation.py:replay_tool_specs` and `replay_investigation.py:recorded_tool_specs` offer sensors once a numeric value was observed before cutoff; they don't independently check current freshness/coverage. `providers/replay.py` omits UNAVAILABLE values but does not give every window a complete quality/coverage explanation; `check_conclusion`/numeric validators do not currently require coverage sufficiency.

**Plan (off by default for new agent-facing restrictions; never disable existing mandatory SDC validation):**

- Add a feature gate such as `QUALITY_AWARE_REPLAY_TOOLS=False`, a versioned `ChannelQuality` contract and an intentionally conservative per-signal `MIN_CHANNEL_COVERAGE` starting **only as a test hypothesis** (0.5 is *not* a universal safety threshold). Define coverage denominator as valid time/exposure in the requested interval, not count of samples; use actual sampling/change-only behavior, approved freshness, collector epochs and quality status.
- Compute from authorized records **received by the investigation cutoff**, keyed by full source/server/machine/channel/axis/NodeId and mapping revision—not `data_item_id` alone. Preserve Good/Uncertain/Bad status for Siemens OPC UA, source/server/receipt timestamps, gaps, clock uncertainty and authorized acquisition scope. For older MTConnect fixture compatibility, use the existing helpers with their known per-item-ID limitation; don't claim Siemens-ready semantics from them.
- Keep **current availability** distinct from **historical-window eligibility**. If stale now, omit or mark unavailable for a current diagnosis, but a past-window query can remain usable if the observations were fresh/valid *then*, as-known at that earlier cutoff. Event/change-only channels such as Execution use their **own update/hold semantics** and do not automatically become stale due to silence.
- In **both** recorded entrypoints, derive the same capability list from the source-aware quality map at the same cutoff. List unavailable/insufficient channels and exact non-sensitive reasons; never claim that a mapping or one historical number proves a valid present reading. Dispatch must enforce the same map, not trust tool descriptions alone.
- Every windowed replay tool returns precise usable coverage, UNAVAILABLE/Bad/Uncertain/stale spans, knowledge cutoff, source/time provenance and `sufficient | insufficient | unknown`. Preserve permitted raw rows/audit metadata, do **not** invent zero or interpolate missing intervals or call silence machine downtime.
- Extend `conclusion_gaps`, `diagnosis_supported` and `verify_numeric_claims` to reject/abstain when *only* insufficient-quality evidence supports a mechanical claim. Independent physical-source evidence (RMI-07) is a separate P0 diagnostic correctness gate; quality alone cannot prove causation. Record the failure category, evidence IDs, time-window coverage and human-review reason.

**Positive/negative tests:** good now vs stale-at-cutoff; stale-current but valid historical window; 30% UNAVAILABLE window at a candidate 50% threshold returns `insufficient` and explicit span; lower coverage vs sufficient; Good→Bad→Good; Uncertain and clock drift; event-only no-updates; two machines sharing IDs; detached or unapproved NodeId; delayed-arriving readings and dual as-of cutoffs; unsupported sensor omitted and logged; only insufficient E5 ⇒ unresolved/escalate, never supported; clean channels, simulator and feature-off fixtures unchanged. Finally perform technician-reviewed physical acceptance using approved Prestige data before real-machine claims.

**Acceptance:** no stale/Bad/unknown or under-covered reading silently becomes trustworthy supporting evidence; no valid historical work is unnecessarily suppressed; no factory/health conclusion is made from missing telemetry. **References:** [SDC-03/05/07/08/15/17/18](SIEMENS_DATA_ACCEPTANCE.md), [RMI-01/04/07](REAL_MACHINE_INTELLIGENCE_ACCEPTANCE.md), [SM-2](MVP_SCOPE.md#fw-sm-gap-events), [SM-5](MVP_SCOPE.md#fw-sm-time-stats).

## How to use this list

- Each item must be assessed against current production modules before starting. Reuse the present Pydantic Graph, ReAct loop, model clients, MTConnect ingestion and evaluation infrastructure instead of building parallel frameworks.
- Keep the authoritative SDC and RMI requirements in place. A MEDIUM scheduling label here never permits invalid/unapproved data, production actions or unsafe diagnostic conclusions.
- For each implementation PR record the existing foundation, changed module, applicable hardware/license/authorization, test cases, measurable pass/fail, and documented/implemented/offline-verified/machine-verified/blocked status.
- Keep traces metadata-only by default. No unapproved machine recordings, alarm text, prompts, sensitive job details or external model transfers.
- The explicit noise decisions from the originating review are not backlog items. Future agents should not turn a deferred item into a default dependency without measurements and documented user approval.
