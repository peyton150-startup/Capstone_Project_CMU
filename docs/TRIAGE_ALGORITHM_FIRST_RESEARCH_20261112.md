## Decision and boundaries

The goal is a **Python-first, measurement-driven rapid triage** in which models are invoked for unresolved causal reasoning, unknown phenomena and non-routine manuals, **not** to repeat validated arithmetic, construct predictable tool arguments, generate standard questions or perform routine sequential inspection. Reuse `ReasoningPolicy` within the current Pydantic Graph; do not replace the graph or change its deep investigation, critic, memory, approval, intervention or verification semantics. Preserve `mode="triage"` read-only, the 90-second deadline and the 6-call default until an explicit matched experiment justifies change. Siemens access/permissions and SDC/RMI quality gates remain independent P0 owners; this file concerns only qualified data **consumed** by triage. No evaluator labels or hidden simulator truth may reach runtime.

**Why:** A0 reported 26 completed known-answer runs, **25/26 timed out**, p50 **87 s**, 170 model questions, 93 model attempts cut off by question time, 16 diagnostic-stage results labeled `uninterpreted`, 24 repeated-call skips, 6 failed requests, **no new test-stage observations**, and one KA-09 two-fault `supported/no_action` false clearance. Root causes were **not judged**, and these counts do not establish any future model-call reduction or accuracy. [A0 source](benchmarks/2026-11-12-triage-a0.md). Code inspection, benchmark observation and research hypotheses are deliberately distinct.

## Proposed minimal architecture (no new framework)

1. **Existing monitor / authorized adapter → `Incident`:** alert+source+trigger/capture cutoffs; deduplicate (TRI-27 separately); do not assume alarm names true machine.
2. **Existing tools + `QualifiedPacketBuilder`**: validated machine roster, channel registry, read-only capability, sensor quality, operating-state-aware intervals, evidence provenance, explicit `unknown` (TRI-17/21/31/33).
3. **`QuestionCompiler` + `TemporalQuestionEvaluator`**: known symptom→typed question, expected observation and executable predicate, four-valued outcome, untouched open rivals (TRI-03/13/16/21).
4. **`ConstraintAwareSelector`**: rank tests by rival discrimination, validated eligibility, cost, prior qualifying reads, falsification and machine coverage; branch after each result, fallback when novel/underdetermined (TRI-07/19/20/34).
5. **`FeatureEngine`** reuses existing screening/evidence arithmetic for reproducible state-conditioned temporal/number features; no causality inferred from correlation (TRI-25/26/33).
6. **Optional `CandidateEngine`**: validated fault signatures and bounded consistency-based conflict sets; **offline only** until performance and physics validity pass (TRI-18/22).
7. **`HybridTriagePolicy(ReasoningPolicy)`**: the **existing Pydantic Graph** requests typed plan/decision/interpretation; Python handles routine known cases; use LLM only for unknown, conflicting or unproven causal questions, possibly procedures. No deep-policy changes.
8. **`TriageDispositionGate` → typed report**: supported finding **only when justified**, otherwise sufficient alert/unknown/escalate; human action remains outside triage. Preserve `needs_deep_run` semantics (TRI-02/10/22).

**Architectural rule:** information learned only after the trigger may enter a current snapshot but cannot be misrepresented as pre-trigger evidence; historical examples, manuals and derived scores cannot masquerade as new independent live sensor channels.

## Evaluation design: replace model calls only when it passes

Do **not** relabel existing **A0 → A1 hypotheses-first → A2 batching → A3 advisory selector → A4 executable selector** experiments. For algorithm-first changes add clearly separate **B** arms after the targeted P0 safety regression; each B arm changes **one component** while holding input seeds, model/provider routing, budget and capture cutoff fixed:

| Arm | Isolated change | Primary measured outcome |
|---|---|---|
| **B0** | Frozen A0/control plus PR #246 reviewed safety baseline where applicable | Failure/coverage accounting; baseline comparability explicitly documented |
| **B1** | Qualified packet and question-satisfaction evaluator only | Question true/false/insufficient accuracy; valid sensor coverage, wrong closure, false `no_action` |
| **B2** | B1 + Python question-template `plan`; original model `decide` | `plan` model calls removed; first useful evidence latency and plan coverage |
| **B3** | B2 + constraint-aware *advisory* selector; existing policy still executes | Distinguishing-read ranking, no new invalid requests, correlation with eventual useful evidence |
| **B4** | B3 + *executable* contingent selector; fall back to model for ambiguity | Model decisions and p50/p95 latency, timeouts, fault coverage and severe/compound misses |
| **B5** | B4 + Python numeric question interpretation | Interpreted-evidence ratio, preserved diagnostic correctness, actual interpretation calls removed |
| **B6 offline only** | B5 + bounded fault signatures/conflict search; later tiny ML baselines | Multi-fault recall, unknown-fault abstention, calibration, shift tests on held-out seeds/machines |

**Required tracked metrics:** useful qualified evidence recall; exact physical-source and machine coverage; question closure correctness; latest visible evidence; time-to-first valid hypothesis; number of model questions by job and fallback; invalid/repeated/failed tool attempts; latency p50/p95; triage timeouts; false supported `no_action`; missed severe and simultaneous faults; over-escalation of valid benign cases; label coverage and calibration. The 13 A0 known-answer scenarios alone cannot establish deployment-ready generalization or diagnostic accuracy.

**Stop/rollback:** any new unsafe false clearance, unqualified evidence claimed normal, hidden-truth leakage, omitted second fault due to pruning, tool/permission bypass, or unacceptable unknown-fault misses. If a test is too expensive or unavailable, preserve `insufficient` and escalate rather than fabricate a negative test.
